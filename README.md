# File Tidier

책 파일 13만 개가 쌓인 개인 아카이브에서 **이름만 다른 같은 파일**을 찾아내는 도구입니다.
Python 백엔드 + Electron UI 로 되어 있고, 파일을 지우지 않습니다 — 격리 폴더로 옮기는 것까지가 전부입니다.

## 검증

이 프로젝트는 생성형 AI 와 함께 만들었습니다. 그래서 **완료 보고 대신 이 명령의 결과를 믿습니다.**

```
python verify.py
```

```
표본 만들기          0.2초
단위 시험    61건    0.5초    함수 단위 판정 규칙
표본 시험    15건    1.6초    백엔드 명령을 실제로 돌려 결과 JSON 확인
연기 시험     6건    3.0초    앱을 띄워 사람이 쓰는 경로 그대로
벤치마크             0.5초    성능 주장 재현
```

시험은 저장소 안 고정 표본(`tests/make_fixture.py`, 21개 파일)으로 돕니다.
내 PC 의 실제 책 폴더가 없어도 clone 해서 그대로 확인할 수 있습니다.
표본에 담긴 것은 전부 **실제로 오작동을 냈던 파일 모양**입니다.

### 단위 시험만으로는 못 잡았던 것

가짜 데이터로 함수만 확인해서는 안 잡히고, 실제 폴더를 끝까지 훑어야 드러난 문제들입니다.
이것들 때문에 표본 시험과 연기 시험을 따로 두었습니다.

| 무엇 | 어떻게 드러났나 |
|---|---|
| 복구된 파일의 수정시각이 int64 를 넘어 스캔 전체가 죽음 | `sqlite3` 가 `OverflowError` 를 던지는데 캐시가 `sqlite3.Error` 만 잡고 있었다. 정상 파일에서는 안 나오는 값이라 합성 데이터로는 영영 못 잡는다 |
| 백엔드 옵션(`--max-files`)을 만들고 UI 에 연결하지 않음 | 단위 시험은 전부 통과했다. 앱을 띄워야 드러난다 |
| 함수 이름이 겹쳐 행 설명에 진행률이 찍힘 | 문법 검사로는 안 잡힌다. 화면을 봐야 보인다 |

### 판정 규칙은 값으로 못박아 둔다

속도를 위해 본문 정리 쪽을 손댔을 때(초당 2.0 → 5.4개), 지문 값이 바뀌면 캐시가 전부 어긋나고
중복 판정이 달라집니다. 실제 파일 60개로 바꾸기 전후를 대조해 60/60 같은 값임을 확인했고,
그 확인을 `test_fingerprint_pinned` 로 남겼습니다. 규칙을 고치려면 이 값이 왜 바뀌어도 되는지
먼저 설명할 수 있어야 합니다.

## 안전 정책

- 삭제하지 않습니다. 같은 확장자 + SHA-256 완전 일치일 때만 자동 선택 후보로 두고, 실행은 격리 폴더 이동입니다.
- 애매한 것(제목만 같음, 본문만 비슷함)은 참고용 검토로만 표시하고 자동 선택하지 않습니다.
- 이름 변경과 격리는 미리보기를 거쳐 승인 후에만 실행합니다.
- 장치 읽기 오류가 연속 3번이면 스캔을 멈춥니다. 죽어 가는 디스크를 계속 훑으면 손상이 번집니다.

## 실행

```powershell
python file_tidier.py
```

Windows에서는 `FileTidier.vbs`를 더블클릭하면 콘솔 창 없이 화면 프로그램처럼 실행됩니다.

화면과 흐름을 먼저 보고 싶으면 `FileTidier-UI.vbs`를 더블클릭하세요. Edge 앱 모드로 `ui/index.html`을 열어서 Electron 같은 창으로 데모 화면을 보여줍니다.

Electron 버전은 `electron-app` 폴더에 따로 있습니다. 기존 Python/Tkinter 파일은 유지했습니다.

```powershell
cd electron-app
pnpm.cmd install
pnpm.cmd start
```

설치 후에는 `FileTidier-Electron.vbs`를 더블클릭해 실행할 수 있습니다.

Electron 버전의 모드:

- 파일 목록
- 크기 중복
- 내용 중복
- 문장 중복
- 참조 문장 확인
- 제목 중복
- 이름 변경 미리보기

Python 3.11 기준으로 작성했고, 별도 패키지 설치 없이 표준 라이브러리만 사용합니다.

## 기능

- 폴더 선택 후 하위 폴더 포함 여부 설정
- 파일 목록 보기
- 파일명에서 제목 뽑기
- `.zip`, `.cbz` 내부 파일명까지 목록에 표시하고 제목 뽑기
- 파일 확장자 표시 및 확장자 필터
- zip/cbz 내부 확인 켜기/끄기
- 표시 최대 개수 제한으로 큰 폴더 로딩 부담 완화
- 진행 중인 목록/중복 확인 중지
- 깨진 압축파일 또는 너무 큰 압축파일은 `스킵됨` 탭에 표시
- 제목 추출 규칙 미리보기
- 결과 표 헤더 클릭 정렬
- 제목 중복 확인에서 남길 파일 후보 표시
- 같은 크기의 파일 후보 찾기
- SHA-256 해시로 내용까지 같은 중복 파일 찾기
- 최소 파일 크기 필터
- 중복 목록에서 선택한 파일 경로 복사
- 제목 중복 확인
- `.zip`, `.cbz` 안의 파일명까지 확인해서 같은 책 제목으로 보이는 파일 알림
- `aaa.zip`, `aaa.epub`, `[ㅠㅠ]aaa.txt`처럼 앞 태그와 확장자가 달라도 `aaa`로 인식
- 파일명 일괄 변경 미리보기
- 찾기/바꾸기, 정규식 바꾸기
- 찾을 텍스트가 앞/뒤/포함/전체 중 어디에 있을 때 적용할지 선택
- 접두사/접미사 추가
- 번호 붙이기
- 대소문자 변경
- 확장자 유지 옵션
- 이름 충돌, 중복 대상, 변경 없음 상태 표시

## 사용 흐름

1. 상단에서 정리할 폴더를 선택합니다.
2. `파일 목록` 탭에서 전체 파일과 zip 내부 파일명을 먼저 확인합니다.
3. `중복 찾기` 탭에서 크기 후보 또는 내용 중복 검사를 실행합니다.
4. `제목 중복 확인` 탭에서 zip 내부 항목까지 포함해 같은 제목으로 보이는 파일을 확인합니다.
5. `이름 바꾸기` 탭에서 규칙을 입력하고 `미리보기`를 확인합니다.
6. 상태가 `ready`인 항목만 `적용`으로 실제 변경됩니다.

## 파일 목록 검색

- `FileTidier.vbs`를 더블클릭해서 실행합니다.
- 상단 `찾기` 버튼으로 폴더를 선택합니다.
- 기본값은 빠르게 보기 위해 `zip 내부 포함`이 꺼져 있습니다.
- 압축파일 내부 제목까지 보고 싶을 때만 `zip 내부 포함`을 켭니다. 느리면 끄고 바깥 파일부터 확인합니다.
- 결과가 너무 많으면 `표시 최대` 값을 줄입니다.
- 오래 걸리면 상단 `중지` 버튼을 누릅니다.
- `파일 목록` 탭에서 `목록/제목 뽑기(zip 포함)`을 누릅니다.
- 검색어가 비어 있으면 바깥 파일과 zip/cbz 내부 파일명을 모두 보여줍니다.
- 표의 `뽑은 제목` 칸에서 파일명에서 정리된 제목을 볼 수 있습니다.
- `제목 규칙 미리보기`에 파일명을 입력하면 뽑힐 제목을 바로 볼 수 있습니다.
- `뽑은 제목`은 `[태그]`, `(태그)`, 확장자 등을 제거한 제목입니다.
- `제목 중복 확인` 탭의 `그룹`은 같은 `뽑은 제목`으로 잡힌 항목을 구분하는 번호입니다.
- `원래 이름`은 실제 파일명 또는 압축파일 안의 실제 항목명입니다.
- 검색어가 있으면 파일명, 뽑은 제목, 또는 `압축파일 경로 :: 내부파일 경로`에 포함된 항목만 보여줍니다.
- 검색어에 `epub`, `.epub`, `txt`, `.txt`처럼 확장자를 넣어도 필터링됩니다.
- 현재 단계는 압축 내부의 파일명 검색입니다. txt 본문 내용까지 읽는 검색은 별도 기능으로 추가할 수 있습니다.
- 압축파일 하나당 내부 항목은 기본 2000개까지만 확인합니다. 너무 큰 압축파일 때문에 오래 멈추는 것을 막기 위한 제한입니다.
- CP949/EUC-KR 계열 zip 내부 파일명과 `ㄱㅏㄴㅏ`처럼 분리된 한글 자모는 가능한 범위에서 보정합니다.
- 읽을 수 없거나 제한에 걸린 압축파일은 `스킵됨` 탭에서 확인합니다.

## 이름 변경 쉽게 쓰기

`세부 옵션` → `이름 변경`에 **자주 쓰는 규칙** 버튼이 있습니다.

| 버튼 | 하는 일 |
| --- | --- |
| 앞의 [태그] 떼기 | 이름 맨 앞의 `[ ]` `( )` `【 】` 묶음을 뗍니다 |
| 끝의 (2) 떼기 | 이름 끝의 `(2)`, `(3)` 같은 복사본 표시를 뗍니다 |
| 작가명 앞으로 / 뒤로 | 이름에서 작가명을 찾아 `[작가] 제목` 또는 `제목 [작가]`로 맞춥니다 |
| 띄어쓰기 정리 | 밑줄을 공백으로 바꾸고 겹친 공백을 정리합니다 |
| 번호 매기기 | 1, 2, 3… 순서대로 `001` 형식 번호를 붙입니다 |
| 규칙 지우기 | 규칙을 모두 끕니다 |

버튼 하나를 누르면 **그 규칙 하나만** 걸립니다. 다른 규칙은 전부 꺼지므로
버튼 이름과 실제로 일어나는 일이 항상 같습니다. 섞어 쓰려면 그 아래
`직접 규칙 짜기`를 펼치세요.

바로 아래 `예시 이름` 칸에 파일명을 넣으면 **규칙을 건드릴 때마다 즉시**
어떻게 바뀌는지 보여 줍니다. 폴더를 훑지 않으므로 마음껏 눌러 봐도 됩니다.
스캔을 한 번 하면 그 폴더의 실제 파일명이 예시로 들어옵니다.

실제로 바꾸려면 `이름 변경 미리보기`로 스캔한 뒤, 결과 표에서 확인하고
`이름 변경 적용`을 누릅니다.

**적용 범위:** 파일을 하나씩 고르는 게 아닙니다. 규칙 하나가 폴더 전체에
한꺼번에 걸리고, 미리보기에서 `적용 가능`으로 나온 파일이 전부 바뀝니다.
(결과 표의 체크박스는 `격리` 전용입니다.)

## 작가명 자동으로 채우기

`직접 규칙 짜기` 안에 관련 항목이 셋 있습니다.

| 항목 | 하는 일 | 기본 |
| --- | --- | --- |
| 작가명 자동 추출 | 파일명에서 작가를 찾습니다 | 켜짐 |
| epub 정보에서 작가 읽기 | epub 안의 `dc:creator`를 읽습니다 | 꺼짐 |
| 시리즈 전체에 작가명 채우기 | 권수를 뗀 제목이 같으면 나눠 씁니다 | 꺼짐 |

찾는 순서는 **① 파일 안에 적힌 작가 → ② 제목이 똑같은 다른 파일 →
③ (켰다면) 같은 시리즈의 다른 권** 입니다.

파일명에서 알아보는 형태:

- `[작가] 제목`, `【작가】제목`
- `제목@작가`, `작가@제목`
- `작가_제목_1권`, `_작가_제목_1권` (앞에 `_`가 붙어 있어도 됩니다)

밑줄 이름은 조각이 넷 이상이거나, 셋이어도 `1권`·`3화` 같은 권수 표시가
있어야 작가로 봅니다. `my_photo_2024`나 `season_01_final`처럼 평범한
파일명을 작가로 잘못 읽지 않기 위해서입니다. 그래서 `_작가_단편`처럼
권수가 없는 세 조각짜리는 못 알아봅니다.

**시리즈 채우기 주의:** 서로 다른 작품인데 시리즈 제목이 우연히 같으면
엉뚱한 작가가 붙습니다. 그래서 기본으로 꺼져 있고, 켜더라도 미리보기 표를
꼭 확인하세요.

`epub 정보에서 작가 읽기`와 `시리즈 전체에 작가명 채우기`를 같이 켜면,
epub 한 권에서 읽은 작가를 같은 시리즈의 `.txt`에도 넣을 수 있습니다.
한 번 읽은 epub 정보는 캐시에 남아 다음 스캔에서 다시 읽지 않습니다.

이 둘은 실제 파일을 읽어야 하므로 `예시 이름` 미리보기에는 반영되지
않습니다. 스캔 결과 표에서 확인하세요.

## 이름 변경 예시

- `(아이)aaa.zip`, `(아이)bbb.zip`, `(아이)ccc.zip`에서 `(아이)`만 떼고 싶으면 `찾기`에 `(아이)`, `바꾸기`는 비워두고, `위치`를 `앞`으로 둔 뒤 미리보기를 확인합니다.
- 파일명 뒤의 `-완` 같은 꼬리표만 떼고 싶으면 `위치`를 `뒤`로 바꿉니다.
- 파일명 어디에 있든 바꾸려면 `위치`를 `포함`으로 둡니다.

## 책 제목 인식 규칙

- 파일명에서 확장자를 제거합니다.
- 맨 앞의 `[태그]`, `(태그)`, `{태그}`, `【태그】` 같은 묶음 태그를 제거합니다.
- `_`, `-`, `.` 문자는 공백처럼 정리합니다.
- 대소문자는 구분하지 않습니다.

## 스캔 결과 저장하고 다시 열기

한 번 훑은 결과를 파일로 남겨 두고 나중에 그대로 다시 볼 수 있습니다.
결과를 훑어보는 동안 디스크를 다시 읽지 않습니다.

- UI: 스캔이 끝난 뒤 `결과 저장`. 저장한 파일은 `결과 열기`로 다시 엽니다.
- 명령줄:

```powershell
python file_tidier_backend.py duplicates-comprehensive --folder "D:\책" --limit 0 --save-result scan.json
python file_tidier_backend.py load-result --file scan.json --query "제목"
```

`표시 최대`(`--limit`)에 걸린 만큼만 저장됩니다. 전부 남기려면 0으로 두세요.
잘린 경우 파일에 `truncated`로 적히고 UI 상태줄에도 알려 줍니다.
UI와 명령줄의 파일 형식이 같으므로 서로 열 수 있습니다.

## 해시 대장 — 압축해도 살아남는 중복 기준

캐시는 `경로 + 크기 + 수정시각`으로 기억하므로 **파일을 옮기거나 다시 묶으면
잃습니다.** 압축을 풀어 정리한 뒤 다시 묶을 계획이라면, 묶기 전에 해시 대장을
남겨 두세요. 내용의 신원(SHA-256)은 압축하든 말든 그대로입니다.

- UI: `대장 만들기` → 나중에 `대장과 대조`
- 명령줄:

```powershell
python file_tidier_backend.py export-manifest --folder "D:\풀어놓은책" --output 내책.jsonl
python file_tidier_backend.py check-manifest --folder "D:\새로받음" --manifest 내책.jsonl --include-zip
```

대장에는 파일마다 제목·크기·**SHA-256**·**CRC32**가 한 줄씩 들어갑니다(JSONL).
수십만 개가 되어도 메모리에 다 올리지 않고, 도중에 끊겨도 그때까지는 남습니다.

**CRC32를 같이 적는 이유:** zip은 멤버마다 CRC32를 중앙 디렉터리에 적어 둡니다.
즉 압축을 풀지 않고 목록만 읽어도 대장과 맞춰 볼 수 있습니다. 대장에 없는
멤버는 아예 풀지 않고, 겹치는 것만 풀어서 SHA-256으로 확인합니다. CRC32는
32비트라 우연히 겹칠 수 있어서 확인 없이 단정하지 않습니다 — `--no-verify`를
주면 확인을 건너뛰고 압축을 하나도 풀지 않습니다.

파일명이 달라도 내용이 같으면 걸러집니다.

## 다시 읽지 않기 (캐시)

파일 해시(SHA-256)와 본문 지문을 sqlite에 기억해 둡니다. 같은 파일을 다시
스캔할 때는 경로·크기·수정시각이 그대로면 디스크를 읽지 않고 캐시에서
꺼냅니다. 파일을 고치면 수정시각이 바뀌므로 자동으로 다시 읽습니다.

- 위치: `%LOCALAPPDATA%\File Tidier\zip-index.sqlite3`
  (`FILE_TIDIER_CACHE_DIR` 환경변수로 바꿀 수 있습니다.)
- **파일을 옮기거나 이름을 바꾸면 캐시를 잃습니다.** 경로가 키의 일부이기
  때문입니다. 옮길 계획이라면 위의 해시 대장을 먼저 남겨 두세요.
- 500건마다 저장하므로 스캔을 중간에 멈춰도 그때까지 읽은 것은 남습니다.
- 캐시를 지우려면 그 파일을 삭제하면 됩니다. 결과는 같고 첫 스캔만 느려집니다.

## 폴더 제외

검사할 필요 없는 폴더는 애초에 들어가지 않는 것이 가장 확실한 절약입니다.
파일 하나를 열 때마다 백신이 검사하고 동기화 프로그램이 반응하므로, 4~5만 개를
훑으면 그 부하가 그대로 곱절이 됩니다.

- UI: `세부 옵션` → `제외할 폴더`. 쉼표로 여러 개, 전체 경로도 됩니다.
- 명령줄: `--exclude-folders "Dropbox, OneDrive"`

이름만 적으면 어디에 있든 그 이름의 폴더가 빠지고, 전체 경로를 적으면 그
폴더만 빠집니다. 아래는 적지 않아도 **항상 자동으로** 빠집니다.

`_FileTidier_Quarantine`(이 프로그램이 만든 격리 폴더), `$RECYCLE.BIN`,
`System Volume Information`, `.dropbox.cache`, `.git`, `__pycache__`,
`node_modules`, `.thumb-cache`

격리 폴더가 빠지는 것이 특히 중요합니다. 빼지 않으면 방금 격리한 파일을
다음 스캔에서 다시 집어 옵니다.

## 디스크가 이상하면 멈춥니다

읽기 실패라고 다 같지 않습니다. 권한 없음, 스캔 도중 파일이 사라짐, 다른
프로그램이 잠금 - 이런 것은 큰 폴더를 훑으면 늘 몇 건씩 나오고 넘어가도
됩니다. 반면 CRC 오류(배드 섹터), I/O 장치 오류, 장치가 준비되지 않음은
디스크 자체가 상하고 있다는 신호입니다.

뒤쪽이 **연속 3번** 또는 **누적 12번** 나오면 스캔을 멈추고 어떤 파일에서
났는지 보여 줍니다. 죽어 가는 디스크를 계속 훑는 것은 손상을 넓힐 뿐입니다.

```
python file_tidier_backend.py duplicates-comprehensive --folder "D:\책"     --io-consecutive-limit 3 --io-error-limit 12
```

`0`을 주면 그 판정을 끕니다. 둘 다 0이면 예전처럼 전부 넘어갑니다.

## 몇 개만 하고 멈추기

`--limit` 은 **결과를 몇 줄 보여 줄지**일 뿐이라 스캔량과는 상관이 없습니다.
실제로 덜 읽으려면 `--max-files` 를 쓰세요.

```
python file_tidier_backend.py duplicates-comprehensive --folder "E:\내 소설들" --max-files 20000
```

세는 것은 **디스크에서 새로 읽은 파일**입니다. 캐시에서 꺼낸 것은 디스크를
건드리지 않았으니 예산을 쓰지 않습니다. 그래서 다시 돌리면 앞부분은 캐시로
훅 지나가고 예산은 아직 안 읽은 파일에 온전히 쓰입니다. 13만 개를 2만 개씩
일곱 번에 나눠 도는 식이 됩니다.

멈춘 판은 `중간 저장됨 · 이번에 20000개 읽고 멈춤 · 91234개 남음` 처럼
표시되고, 체크포인트가 `partial` 로 남아 다음 스캔이 이어서 합니다.

예산은 **해시 비교와 본문 비교가 나눠 씁니다.** 한쪽만 막으면 나머지가
마음대로 읽어서 옵션이 뜻대로 동작하지 않습니다. (`--include-zip` 을 켰을 때
zip 안을 읽는 것은 아직 예산 밖입니다.)

**부분 스캔 결과는 부분입니다.** 아직 안 읽은 파일과의 중복은 당연히 안
잡힙니다. 다 돌고 나서 판단하세요.

## 중단된 스캔 이어하기

스캔이 끊기면(디스크 이상, 강제 종료, 정전) 어디까지 갔는지와 어떤 파일이
장치 오류를 냈는지를 캐시에 남깁니다. 같은 폴더를 다시 스캔하면 자동으로
이어서 하고, **장치 오류를 냈던 파일은 건너뜁니다.** 이게 없으면 이어하기가
같은 배드 섹터에 다시 부딪혀 곧바로 또 멈춥니다.

해시 캐시가 이미 읽은 파일을 다시 안 읽으므로, 실제로 다시 도는 것은 못 읽은
부분뿐입니다.

- 상태 보기: `python file_tidier_backend.py scan-status`
- 기록 지우기: `python file_tidier_backend.py scan-status --clear`
- 건너뛴 파일까지 다시 시도: `--no-resume`

건너뛴 파일은 결과에 `지난번 읽기 실패한 N개는 건너뜀`으로 표시됩니다.
숨기지 않으니 몇 개가 빠졌는지는 항상 보입니다.

## 큰 폴더에서 주의할 점

- 최소 파일 크기 기본값은 4 KiB입니다. 그보다 작은 파일은 내용이 같은 것이
  너무 많아 결과만 지저분해지고 해시 후보만 불어납니다. 필요하면 UI에서 낮추세요.
- 본문 비교는 파일을 읽는 즉시 지문만 남기고 원문을 버립니다. 그래서 대상
  폴더가 커져도 메모리 사용량이 크게 늘지 않습니다.
- 중복 찾기는 디스크를 가장 혹사시키는 작업입니다. 큰 폴더를 처음 훑을 때는
  다른 대용량 작업과 겹치지 않게 하세요. 두 번째부터는 캐시가 받아 줍니다.
- **백신 실시간 검사**가 파일을 열 때마다 따라 붙습니다. 4~5만 개를 훑으면
  검사도 4~5만 번입니다. 책 폴더를 백신 예외 목록에 넣으면 크게 줄어듭니다.
  (노턴 360 기준: 설정 → 바이러스 백신 → 검사 및 위험 요소 → 검사에서 제외할
  항목. 보안 설정이므로 직접 하셔야 합니다.)
- **동기화 폴더**(Dropbox, OneDrive 등)는 `제외할 폴더`에 넣으세요. 온라인
  전용 파일이 섞여 있으면 읽는 순간 통째로 내려받습니다.

## 안전 장치

- 중복 파일 삭제 기능은 아직 넣지 않았습니다. 중복으로 잡힌 파일은 `선택 격리`로
  `_FileTidier_Quarantine` 폴더에 옮길 뿐이고, 지우는 것은 직접 확인 후 하세요.
- 이름 변경은 적용 전에 미리보기를 거칩니다.
- 이미 존재하는 파일명이나 같은 대상명으로 겹치는 변경은 `ready`가 되지 않습니다.
- 읽기에 실패한 파일은 조용히 넘어가지 않고 `스킵됨` 탭에 이유와 함께 남습니다.
- 장치 읽기 오류가 쌓이면 스캔을 멈춥니다. 디스크가 상하는 중일 수 있어서
  계속 훑지 않는 편이 낫습니다. 위의 `디스크가 이상하면 멈춥니다` 참고.
